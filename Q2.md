# Q2, Keeping a 40-Minute Agent on Course

## Problem
By minute 25, agents in this shape reliably start to drift: skipping questions, re-asking answered ones, losing the thread of what has been captured.

Describe how you would keep the agent as sharp at minute 35 as it was at minute 3. Be concrete about what lives in the model's context versus outside it, what triggers a change, and how the agent recovers information it needs but is no longer carrying. Then tell us what breaks first in your design and how you would detect it.

## Possible solution

My preferred solution would be  to break up the 130 questions into 2 or 3 groups that are independent and related (the questions don’t have to be answered in the order in the form) and have 2 or 3 connections to different fine-tuned models that will handle each set of questions. The WebSocket connections would be established at the start of the call and used as needed for each section.

Otherwise keeping the architecture as described in the problem statement, here are my thoughts.

It seems the voice model is Speech-to-Speech (since the conversation history is audio-native and accumulates on the model side).

1. The state (which questions were filled)  should be maintained independently by the agent outside of the model

2. Use of the tool calling functionality in the model response to call an appropriate function/script (on the agent orchestrator side) to maintain the state and track where we are

3. Update the system instructions after each question to indicate to the model which questions were already answered to prevent drift

The main problem is that the state is maintained independently in two places and so can get out of sync, this can happen for example if two questions get filled by the same utterance (for example: “I live by myself and don’t have any children” could fill two slots), but the response will only have one tool call. This can be detected when the next question is answered, it would seem that a question/slot was skipped.
